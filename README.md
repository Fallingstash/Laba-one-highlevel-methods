## Описание

Консольное приложение на Kotlin, которое проверяет, может ли пользователь выполнить действие над ресурсом.
Проверки идут в таком порядке: логин, пароль, действие, формат пути и объёма, существование ресурса, права доступа, максимальный объём.
Программа работает «тихо»: ничего не выводит (кроме справки) и возвращает статус-код.

Пароли хранятся в виде хэшей SHA-256 с индивидуальной случайной солью (`java.security.MessageDigest`, `SecureRandom`).
Сравнение хэшей выполняется через `MessageDigest.isEqual` (время сравнения не зависит от места расхождения).
Все данные (пользователи, дерево ресурсов, права) хранятся в коде, в файле `Data.kt`.

## Требования к окружению

* JDK (проверено на 25) с утилитой `jar`
* Компилятор `kotlinc` (проверено на 2.4.20)
* Bash: Git Bash или WSL (для `.sh` файлов)
* Библиотека `kotlinx-cli` 0.3.6, лежит в `lib/kotlinx-cli-jvm-0.3.6.jar`

Если jar-файла в `lib/` нет, скачать его можно так:

```bash
mkdir -p lib
curl -L -o lib/kotlinx-cli-jvm-0.3.6.jar \
  https://repo1.maven.org/maven2/org/jetbrains/kotlinx/kotlinx-cli-jvm/0.3.6/kotlinx-cli-jvm-0.3.6.jar
```

## Сборка

```bash
bash build.sh
```

Результат: файл `app.jar` в корне проекта (в него упакованы код, стандартная библиотека Kotlin и `kotlinx-cli`).

## Запуск

```bash
java -jar app.jar --login alice --password qwerty --action read --resource A.B.C --volume 10
```

или через скрипт:

```bash
bash run.sh --login alice --password qwerty --action read --resource A.B.C --volume 10
```

Код ответа смотреть так: `echo $?`.

### Аргументы

| Флаг | Описание |
|------|----------|
| `--login` | Логин пользователя |
| `--password` | Пароль пользователя |
| `--action` | Действие: `read`, `write` или `execute` (строчными буквами) |
| `--resource` | Путь до ресурса через точки, например `A.B.C` |
| `--volume` | Запрашиваемый объём, целое неотрицательное число |
| `-h`, `--help` | Показать справку |

Имя каждого ресурса: не более 20 символов из `A-Z`, `a-z`, `0-9`, `_`.

### Коды ответа

| Описание | Код |
|----------|-----|
| Успешное выполнение | 0 |
| Запрошена справка (или неверный формат запуска) | 1 |
| Неверный пароль | 2 |
| Неверный логин | 3 |
| Неизвестное действие над ресурсом | 4 |
| Нет доступа | 5 |
| Несуществующий ресурс | 6 |
| Некорректный формат ресурса или объёма | 7 |
| Превышение максимального объёма | 8 |

## Тестовые данные

Дерево ресурсов (в скобках максимальный объём):

```
A (100)
├── B (50)
│   └── C (20)
└── D (30)
Docs (200)
└── Reports (100)
```

Пользователи и права (права наследуются потомками):

| Логин | Пароль | Права |
|-------|--------|-------|
| `alice` | `qwerty` | `A`: read, write |
| `bob` | `hunter2` | `A.B`: read; `Docs`: execute |

Пароли указаны только для тестирования, в программе хранятся лишь соль и хэш.

## Тесты

```bash
bash test.sh
```

Скрипт запускает программу с набором аргументов (по одному кейсу на каждый код ответа 0–8), для каждого выводит `OK` или `FAIL` и в конце итог, например `9/9`.

## Принятые решения

* Если право на ресурс не задано, доступ запрещён (по умолчанию доступ закрыт).
* Право на родительский ресурс действует на всех его потомков; право на потомка не даёт доступа к родителю.
* Проверка прав идёт по сегментам пути, а не по строкам, поэтому право на `A.B` не распространяется на `A.BX`.
* Значения `--action` и `--volume` читаются как строки и проверяются в коде, чтобы возвращать коды 4 и 7, а не код ошибки парсера.
* Объём `0` допустим; отрицательный и нечисловой объём даёт код 7.
* Справка обрабатывается до разбора аргументов библиотекой, поэтому код 1 возвращается и для `-h`/`--help`, и для неверного формата запуска.
